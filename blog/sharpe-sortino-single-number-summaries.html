Sharpe Ratio, Sortino Ratio, and the Problem With Single-Number Summaries

Iqbal K I · May 2026 · 5 min read

Ask for "the" performance metric of a strategy and someone will usually hand you a Sharpe ratio. It's a reasonable default — return per unit of volatility, easy to compute, easy to compare across strategies. It's also a single number standing in for a return distribution, and single numbers are always lossy summaries. The question worth asking isn't "is Sharpe useful" — it clearly is — but "what does this particular lossy summary throw away."

Sharpe penalizes upside volatility too

Standard deviation doesn't distinguish between a strategy that spikes upward unpredictably and one that spikes downward unpredictably — both count against it equally. For most investors, the two aren't remotely equivalent. This is the whole motivation behind the Sortino ratio, which only penalizes downside deviation. In practice, a strategy with a mediocre Sharpe ratio and a strong Sortino ratio is often a strategy with positively skewed returns — worth a second look, not a pass.

Neither metric sees tail risk properly

Both ratios are built on variance-like measures, which means both under-react to fat tails. A strategy that's stable 98% of the time and catastrophic in the remaining 2% can post an excellent Sharpe ratio right up until the tail event happens. This is precisely the failure mode that measures like maximum drawdown and Conditional Value-at-Risk are designed to catch, and why I never report a Sharpe ratio without a drawdown figure sitting next to it.

The period you measure over is doing a lot of work

Sharpe and Sortino ratios are both period-dependent in ways that get glossed over more than they should. A ratio computed over a calm two-year window and one computed over a period spanning a volatility shock are not comparable numbers, even for the identical strategy. When I evaluate the regime-dependent agents from my published work, I report these ratios separately by volatility regime for exactly this reason — the blended number hides more than it reveals.

A risk-adjusted return metric is a compression algorithm. Useful for comparison, dangerous if you forget what got thrown away in the compression.

None of this is an argument against using these metrics — I use them constantly. It's an argument for never using just one, and for always asking what a metric was built to ignore before letting it settle an argument.
