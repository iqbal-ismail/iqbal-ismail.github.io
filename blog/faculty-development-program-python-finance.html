Notes From My First Faculty Development Program on Python for Finance

Iqbal K I · March 2026 · 4 min read

Running the International Faculty Development Program on Financial Analytics Using Python at Alliance University was the first time I'd taught code to a room where every single person already had a career. It changed how I think about teaching more than any single course I'd taken as a student.

The blank-file problem is worse for experienced people

Students who've never coded expect to be confused; it's the default state of being new at something. Faculty members with fifteen years of teaching finance, sitting in front of a blank Python file, often carry a much heavier expectation that things should already make sense to them — and the friction that comes from that mismatch is real. The single most useful adjustment I made mid-program was explicitly naming that expectation out loud on day one, so the confusion stopped feeling like a personal failure and started feeling like a normal part of the process.

Anchor everything to a familiar calculation

Abstract syntax doesn't land. What did land was starting every new concept — loops, functions, dataframes — from a calculation the room already did by hand: portfolio variance, a simple moving average, a CAPM beta. Once the code was clearly just automating something they already understood conceptually, the syntax stopped being the point of anxiety and became a means to an end they already cared about.

The real value wasn't the syntax

By the end of the program, most participants weren't going to remember pandas method names — that was never realistic in a few days. What seemed to genuinely stick was a mental model: that a question like "how did this portfolio's risk change over the last five years" is a question you can now ask a dataset directly, instead of a question that requires someone else to build you a spreadsheet first. That shift in what feels askable is, I think, the actual outcome worth optimizing for in these programs.

Teaching people to code isn't really teaching syntax. It's teaching them that a question they used to outsource is now one they can ask themselves.

I ran a related workshop on investment analysis and portfolio management using real-time data at Christ (Deemed to be University) the year before, and the same pattern held there too: start from a question people already know how to ask by hand, and the code follows naturally.
